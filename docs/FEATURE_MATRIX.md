## Overview

This document lists all features by plan tier (FREE, STANDARD, PREMIUM) organized by functional area. Use this for:
- Marketing comparison pages
- Customer emails ("Here's what you have access to…")
- Feature announcements
- Admin onboarding
- In-app feature gates

**Pricing:**
- **FREE** — Forever free, no credit card required
- **STANDARD** — $29/month or $290/year (save 17%)
- **PREMIUM** — $79/month or $799/year (save 15%)

Early bird discount (20% off) available to FREE users within 30 days of signup.

## 📋 Implementation Notes

### Feature Gates
Feature gates live in `src/lib/feature-gates.ts`. When adding new features:
1. Register the feature in the gates file
2. Check `canAccessFeature(userId, featureName)` in components/API routes
3. Update this matrix + memory entry

### Plan Configuration
- Plan model fields: `prisma/schema.prisma`
- Plan-specific data stored in `featuresJson` (JSON, auto-generated per tier)
- Pricing IDs: See `project_stripe_lessons.md` in memory

### Admin Feature Checks
All admin pages check `canAccessFeature()` on load. If author lacks access, they see "Upgrade required" or the feature is hidden.

### Database Migrations
All new tables require:
- Migration file in `prisma/migrations/`
- Supabase GRANT statements (see `project_supabase_grants.md`)
- Apply via `apply_migration` MCP tool (no local env vars)

## 📝 How to Update This Document

**When you ship a new feature:**
1. Update the relevant section above (or add a new section if needed)
2. Update this file in git: `docs/FEATURE_MATRIX.md`
3. Run the `sync-feature-matrix-html.sh` script (or manually update `AuthorLoft_Feature_Matrix.html`)
4. Save a memory entry: `project_feature_<name>.md` with implementation details
5. Update `MEMORY.md` to link the new memory entry

**Audit cadence:** Quarterly (or after major features ship)
